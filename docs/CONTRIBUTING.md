## Committing

If you want to commit a change, use the following format

```
Path: Change
```
### Example

```
/src/driver/ps2-mouse.c: Add a basic ps2 mouse driver.
```

## Getting started

### 1. Fork the repository

Create a fork of the Waddle repository.

### 2. Clone your fork

```
git clone https://github.com/the/url/of/the/fork
```

### 3. Create a branch

```
git checkout -b example
```

Please use a good and comprehensible branch name.

## Pull Requests

Before opening a Pull Request:

* Make sure the project builds.
* Test your changes.
* Explain what your changes do.
* Explain why the changes are needed.
* Mention any known limitations.
* Update documentation if necessary.

Please use a short and descriptive title.

## Issues

### Bug Reports

When reporting a bug, provide as much useful information as possible.

Include:

* What happened
* What you expected to happen
* Steps to reproduce the problem
* Hardware information, if relevant
* Waddle version or commit
* Build environment
* Relevant logs or error messages

## Documentation

If your change modifies how something works, update the relevant documentation.

Documentation contributions are welcome even when they do not involve code.

Useful documentation includes:

* Installation instructions
* Build instructions
* Development guides
* Hardware support
* Architecture documentation
* API documentation
* Troubleshooting guides
* Examples

## Review Process

Pull Requests may be reviewed by project maintainers and other contributors.

Reviewers may request:

* Changes to the implementation
* Additional tests
* Documentation updates
* Changes to the code style
* Simplification of the implementation

Please treat review comments as part of the development process.

## Questions

If you are unsure about something, open an issue or start a discussion in the repository.
